## Oferta âncora

### DGC Sprint Operacional

Uma entrega curta e fechada para resolver uma dor operacional específica com sistema, automação ou dashboard.

Promessa curta:

> Tiramos um processo do improviso e colocamos em uma ferramenta funcional, com escopo fechado e entrega rápida.

## Esteiras de oferta

### 1. Diagnóstico Operacional

Para quem:
- cliente tem dor, mas não sabe explicar o sistema;
- cliente pede “um app/sistema” sem escopo;
- Gabriel/Danilo precisam entender se vale pegar.

Entregáveis:
- mapa do processo atual;
- principais gargalos;
- recomendação de solução;
- proposta de Sprint Lite ou Pro.

Preço inicial sugerido:
- R$ 300 a R$ 700.

Pode ser abatido se fechar projeto maior.

### 2. Sprint Operacional Lite

Para quem:
- uma automação simples resolve;
- um dashboard já dá visibilidade;
- uma planilha precisa virar tela;
- escopo cabe em poucos dias.

Preço inicial sugerido:
- R$ 1.500 a R$ 3.000.

Prazo:
- 5 a 10 dias úteis.

Limites:
- 1 fluxo principal;
- sem multiusuário complexo;
- sem app mobile nativo;
- sem integrações críticas de escrita;
- sem “só mais uma coisinha” fora do escopo.

### 3. Sprint Operacional Pro

Para quem:
- precisa de pequeno sistema interno;
- precisa de CRUD, dashboard e exportação;
- precisa integrar com API/planilha;
- existe operação real por trás.

Preço inicial sugerido:
- R$ 3.500 a R$ 8.000.

Prazo:
- 2 a 4 semanas.

Limites:
- 1 módulo central;
- até 3 perfis de usuário;
- integração read-only preferencial;
- deploy simples;
- logs e backup mínimos.

### 4. Manutenção Operacional

Para quem:
- já tem sistema entregue;
- quer suporte, hospedagem e pequenas melhorias.

Preço inicial sugerido:
- R$ 300 a R$ 1.500/mês.

Regra:
- suporte não é desenvolvimento ilimitado;
- melhorias entram por pacote ou sprint separada.

## Critérios para escolher pacote

Use esta regra:

```text
Dor confusa -> Diagnóstico
Dor clara + solução pequena -> Lite
Dor clara + sistema pequeno -> Pro
Sistema já entregue -> Manutenção
```

## Sinais de projeto bom

- O dono sente a dor.
- O processo acontece toda semana ou todo dia.
- Existe planilha, WhatsApp ou papel tentando resolver.
- Dá para medir antes/depois.
- O cliente consegue pagar sinal.
- Escopo cabe em uma frase.

## Sinais de projeto ruim

- Cliente não sabe quem vai usar.
- Cliente quer copiar um produto gigante.
- Cliente fala muito de ideia e pouco de operação real.
- Cliente só paga se “der certo depois”.
- Cliente quer integração financeira de escrita sem contrato.
- Cliente quer tudo urgente, barato e aberto.

## Frase comercial base

> A DGC ajuda empresas pequenas a transformar processos manuais em sistemas e automações simples. A gente começa pequeno: escolhe uma dor operacional, fecha escopo, entrega uma primeira versão funcional e mede se reduziu retrabalho.
