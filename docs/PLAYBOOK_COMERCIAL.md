# DGC Hub — Playbook Comercial v0.1

Status: operacional inicial.
Data: 2026-06-19

## Objetivo

Evitar que a DGC aceite projeto grande, vago ou ruim. Toda conversa comercial deve reduzir incerteza e transformar dor em escopo pequeno.

## Fluxo de lead

```text
Contato inicial
  -> Triagem de 10 minutos
  -> Diagnóstico pago ou proposta direta
  -> Escopo fechado
  -> Sinal
  -> Execução
  -> Aceite
  -> Manutenção opcional
```

## Perguntas de triagem

1. Qual processo está dando mais retrabalho hoje?
2. Quem executa esse processo?
3. Quantas vezes por semana/mês isso acontece?
4. Como vocês fazem hoje? Planilha, WhatsApp, papel, sistema?
5. O que dá errado com mais frequência?
6. Quanto tempo ou dinheiro isso consome?
7. Quem vai usar a solução?
8. Quem decide e quem paga?
9. Existe prazo real ou é apenas vontade?
10. Se resolvermos só uma parte em 10 dias, qual parte teria mais valor?

## Como transformar conversa em escopo

Sempre converter frases vagas:

- “Quero um sistema de gestão” -> “Qual processo específico precisa sair da planilha primeiro?”
- “Quero automatizar WhatsApp” -> “Qual mensagem/ação acontece repetidamente?”
- “Quero dashboard” -> “Quais 3 números você precisa ver toda semana?”
- “Quero um app” -> “Quem usa, fazendo qual tarefa, em qual momento?”

## Regra do escopo pequeno

Uma primeira entrega só pode ter:

- uma dor principal;
- um usuário principal;
- um fluxo principal;
- uma forma de medir resultado.

Se tiver mais que isso, quebrar em fases.

## Política de pagamento sugerida

Para Sprint Lite/Pro:

- 50% de entrada;
- 50% na entrega/aprovação;
- manutenção separada.

Para diagnóstico:

- 100% antes ou no agendamento.

## Red flags

Não avançar sem cuidado se o cliente disser:

- “É simples, é só fazer igual o sistema X.”
- “Depois que vender eu pago.”
- “Não precisa documentar, vai fazendo.”
- “Quero mudar tudo no meio se eu tiver ideia.”
- “Meu sobrinho quase fez isso.”
- “Preciso disso para ontem, mas meu orçamento é baixo.”
- “Não tenho tempo para explicar o processo.”

## Script curto de posicionamento

> A gente não começa prometendo um sistema gigante. Primeiro escolhemos uma dor operacional clara, entendemos como vocês fazem hoje e entregamos uma versão funcional pequena. Se ela economizar tempo ou reduzir erro, evoluímos em fases.
