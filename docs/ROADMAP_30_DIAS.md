# DGC Hub — Roadmap 30 dias v0.1

Status: plano inicial executável.
Data: 2026-06-19

## Meta dos 30 dias

Sair de “ideia de software house” para operação mínima capaz de vender e entregar uma Sprint Operacional pequena.

## Semana 1 — Fundação comercial e operacional

Objetivo: Gabriel e Danilo saberem o que vendem e para quem.

Entregas:
- validar `DGC_OPERATING_SYSTEM.md`;
- validar `OFERTAS_E_PRECIFICACAO.md`;
- validar `PLAYBOOK_COMERCIAL.md`;
- escolher 1 nicho inicial para abordagem;
- criar lista de 20 leads possíveis;
- criar template de diagnóstico;
- criar template de proposta.

Critério de pronto:
- qualquer lead pode ser triado usando o playbook;
- a DGC consegue explicar sua oferta em 30 segundos.

## Semana 2 — Ativos reutilizáveis

Objetivo: reduzir tempo de proposta e entrega.

Entregas:
- template de briefing técnico;
- checklist de entrega;
- base de proposta comercial;
- base README para projetos de cliente;
- decidir stack padrão por tipo de entrega;
- criar esqueleto `systems/base-dashboard` ou documentar antes de codar.

Critério de pronto:
- uma conversa real vira proposta em menos de 1 hora.

## Semana 3 — Primeiro case/piloto

Objetivo: testar a oferta em contexto real.

Entregas:
- selecionar 1 lead ou projeto interno;
- fazer diagnóstico;
- fechar escopo de uma dor;
- criar plano markdown;
- executar protótipo funcional pequeno.

Critério de pronto:
- existe uma demo real, mesmo que simples;
- a demo resolve uma dor específica, não genérica.

## Semana 4 — Empacotar e vender melhor

Objetivo: transformar aprendizado em oferta mais vendável.

Entregas:
- revisar preço com base no esforço real;
- criar página/one-pager simples da DGC;
- documentar case/piloto;
- ajustar playbook comercial;
- definir manutenção recorrente;
- escolher próximo nicho ou repetir o mesmo.

Critério de pronto:
- DGC tem pitch, proposta, case e processo de entrega.

## Backlog priorizado

### P0 — Agora

- validar posicionamento;
- validar oferta Sprint Operacional;
- criar templates comerciais;
- escolher nicho inicial.

### P1 — Depois da primeira validação

- base técnica dashboard;
- base automação WhatsApp;
- página pública simples;
- CRM simples de leads.

### P2 — Só depois de venda/case

- produto SaaS próprio;
- automações internas avançadas;
- multi-tenant;
- billing;
- portal de cliente.

## Anti-escopo dos primeiros 30 dias

Não fazer ainda:

- SaaS completo;
- sistema multi-tenant complexo;
- landing page perfeita antes de oferta validada;
- automação WhatsApp frágil sem provedor confiável;
- aceitar projeto gigante para “ganhar portfólio”;
- criar tecnologia sem demanda real.
